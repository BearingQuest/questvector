# 0032. Summary guardrails, resume-style export and a check of the exported file

- **Status:** Accepted
- **Date:** 2026-11-27

## Context
Owner decisions, 27 Nov 2026 (backlog item 5): build the guardrails (PRD R14), a resume-style export that screening software can read (R9) and a check of the exported file (R10) in one pull request, as three commits. The guardrails flag and strip but don't block. The 20-year cutoff is opt-in. The desktop export keeps no summary for now (CLI only).

Why: the 5 Nov 2026 Anthropic live run appended an italic note naming the trap keywords after an accurate summary ([ADR-0018](0018-anthropic-thinking-off.md)); the Ollama runs invented facts and added "Here is..." preambles ([ADR-0012](0012-ollama-thinking-off.md)); the 27 Oct real-dossier run inflated depth ("hands-on") and merged facts across roles. Today's export is a private match report plus the whole dossier, not a resume.

## Decision

### Part 1: summary guardrails (R14)
- **Prompt.** `_NARRATIVE_SYSTEM_PROMPT` and the user-turn tail in `questvector/core/llm.py` ask for one first-person paragraph only (no heading, preamble, note, list or markdown, nothing after it), only facts in the excerpts, no titles, metrics, numbers, dates, durations, employers or technologies that aren't there, no depth claim ("hands-on", "expert", "deep") the excerpts don't make, and say the job description shows what to emphasize but is not a source of facts about the candidate. Provider-neutral; the thinking settings of ADR-0012 and ADR-0018 are untouched. `dossier_context_for_prompt` is now the one place that builds the text sent (the first 20 capability bullets), used by the CLI, the desktop and the check.
- **Output check** (`questvector/core/guardrails.py`), run on every generated summary before it is shown or exported:
  - *Strip*, and report what was removed: a heading or "Here is ...:" line before the summary; after it, a second paragraph, a horizontal rule, a whole-line italic, bracketed or parenthesised note, a "Note:" line. If nothing recognizable would be left, the text is kept as is.
  - *Flag, don't block*, per sentence: a **number** not in the sent text (compared exactly after dropping commas; "31%", "$1.8M", "7+"); a **capitalized name or technology term** not in the sent text (mid-sentence capitalized words, acronyms and mixed-case words, each with an optional following number, so "SOC 2" and "ISO 27001" are single terms); **third-person pronouns** (he, she, his, her, hers, him, himself, herself, "the candidate"; they, them, their, theirs and themselves only when the sentence has no first-person word); a **depth word** (hands-on, expert, expertise, deep, extensive, advanced, mastery, seasoned, proficient, specialist) the sent text doesn't use.
  - *"Appears in the dossier"* means the text that was sent to the model (not the job description, not Chronology), normalized the [ADR-0027](0027-keyword-normalization.md) way: every token of the term, after `normalized_tokens`, is in the sent text's token set. So "K8s", "CI/CD" and "SOC 2" meet "Kubernetes", "cicd" and "soc2". A digit inside a word ("K8s", "S3") is not a number.
  - Flags show in `qv export` output, in `qv export --json` (new; `narrative` holds `text`, `removed`, `flags`) and in the desktop result (`narrative`, `removed`, `flags`), rendered as text ([ADR-0029](0029-desktop-text-only-csp-bundle-names.md)). The export still runs. Flags never go into the exported file: the exporter only receives the cleaned text.

### Part 2: resume-style export (R9)
- **Option.** `qv export --style {report,resume}`, default `report` (today's output, unchanged). `--cutoff-years [N]` takes a whole number from 1 to 60 and means 20 when given without a value (`nargs="?"`); it needs `--style resume`. The desktop export has a Style choice and a checkbox for the 20-year cutoff; its resume has no summary (CLI only for now, backlog item 15). `export_bundle` and the bridge keep their report behavior when no style is given.
- **Role heading grammar** (resume only): `## Title — Employer (Mon YYYY – Mon YYYY)` or `(... – Present)`. The em dash (as the README and fixtures already use) separates title from employer; the dates are the last parenthetical; months are three-letter English (Jan to Dec, any case); the range separator is an en dash or a hyphen; the end can't be before the start. `parse_role_heading` gives a `Role` (title, employer, start, end or `None`), stored on `ChronologyEntry.role`. With `require_roles`, one `ParseError` names `Chronology.md`, every heading that doesn't fit with the reason, and the form with an example. Report style accepts any heading, so existing dossiers keep working; to use the resume style add months to the parenthetical by hand (the error shows how). A parsed role contributes only its title and employer words as keywords, so month names never become keywords and scores don't change. The `qv launch` Chronology stub now shows the new form (existing workspaces are untouched). No migration tool: a tool can't invent the months.
- **Contact.** An optional `Contact.md` in the workspace, `Key: value` lines: `Name` and `Email` required; `Location`, `Phone`, `LinkedIn`, `GitHub`, `Website`, `Portfolio` optional. Validated: an unknown or repeated key is an error; single-line values without control characters; a simple email pattern; a phone with 7 to 15 digits; https-only URLs with a host and no user name. It is not part of `Dossier`, not created by `qv launch`, and `llm.py` never imports it, so it cannot reach a narrative prompt (a test runs the CLI with sentinel values and checks the prompt). It is never printed.
- **Layout** (`questvector/core/resume.py` chooses the content, `exporter.export_resume` lays it out): the name; a location, email, phone line; a profile-URL line (email as `mailto:` and URLs as real hyperlinks: DOCX external relationships, PDF link annotations); Summary (when given); Core Capabilities (domain names only, one short line, up to 8); Experience, newest first, each a title line then `Employer | Mon YYYY – Mon YYYY`, then up to 6 bullets in file order; Earlier Career (cutoff only); Selected Results (the first bullet of up to 5 Impact groups). Left out, and reported in the CLI and window (never in the file): capability bullet text, role bullets beyond 6, Impact beyond the first bullet of 5 groups, and the match score, table, gaps and negation warnings. Bullets are a literal "• " in Normal paragraphs: python-docx's List Bullet numbering carries tab definitions. Margins 0.75 in, no header or footer parts.
- **Escaping.** Every string that reaches a ReportLab `Paragraph`, in both styles, goes through one helper (`_para_text`), because `Paragraph` reads markup: before, a dossier line with "R&D" or "< 100 ms", or an AI summary containing `<a href=...>`, was parsed as markup.
- **Cutoff.** "Today" is a required argument of `export_resume` and `build_resume`, set once by `cli._today()` and the bridge's `_today()` (tests replace them), so no test reads the clock. The cutoff date is today minus N years (29 Feb becomes 28 Feb). A role whose end month is before the cutoff month goes to Earlier Career as dateless "Title, Employer"; Present never moves. No year before the cutoff year may appear in the file. A role that **started** before the cutoff year but is still inside it (a straddling role), or whose title or employer contains such a year, is **refused with an error naming its heading** (owner decision: it can't be shortened without misstating a date, so the owner splits the role or changes its dates). Any other line (a role or result bullet, a capability domain, a summary sentence) that mentions such a year is left out and counted in the notes. The check runs before any narrative network call.
- **PDF page count.** ReportLab knows it, so `qv export --style resume --format pdf` prints "PDF pages: N" and `--json` has `pdf_pages`. A DOCX isn't rendered here, so no DOCX page count is given (Part 3).

## Consequences
- **Accepted false positives** (each pinned by a test): naming the target employer from the posting ("I want to bring my AWS skills to Quillon Systems") is flagged; a capitalized common noun mid-sentence is flagged; singular and plural forms of a capitalized word don't match each other (no stemming, as in ADR-0027); "expertise" is flagged when the dossier says "expert".
- **Accepted misses** (each pinned by a test): a sentence-initial plain capitalized word ("Datadog dashboards ...") isn't checked; spelled-out numbers ("seven years") aren't; lowercase technology names aren't; "they" about a team after "I" is not flagged; an invented fact in common words isn't caught. The check is a review aid, not proof that a summary is accurate.
- The check cannot know the model's output is true, only what it contains that the dossier text doesn't.
- **Resume style:** the section headings are plain words screening software usually knows, but nothing here proves a given screening system reads the file well; Part 3's check only looks for the layout features R9 forbids. Dossiers need months in their role headings before the resume style works, and the owner adds them by hand. Year checks apply to the resume's body lines, not to the contact block, so a phone number or URL that contains a year-like group is left alone. A straddling role blocks the cutoff export until the dossier is edited.
